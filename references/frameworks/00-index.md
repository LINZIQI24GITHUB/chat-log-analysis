# 框架索引：什么问题，用什么理论看

分析前先在这里选框架，不要凭直觉写。每个框架都只提供「看什么」，
不提供「他是什么人」——单方聊天记录不足以判定人格或依恋类型。

| 用户的问题 | 主框架 | 辅助框架 | 主要看什么 |
|---|---|---|---|
| 他爱不爱我 / 在不在乎 | 投入模型（Rusbult） | 依恋维度、关系维持策略 | 满意度、替代选项、已投入成本；谁在主动维持 |
| 是不是渣 / 有没有问题 | Gottman 四骑士 + 红旗清单 | 一致性检验 | 批评/防御/蔑视/筑墙；承诺与行为是否一致 |
| 该不该分 / 要不要继续 | 投入模型 + 相互依赖 | 阶段模型 | 三条底线得分、退出成本、可逆性 |
| 我们怎么变成这样的 | Knapp 阶段模型 | 追—逃模式 | 从初识到停滞，每个阶段的转折点 |
| 为什么总是吵架 | Gottman 修复尝试 + 追—逃 | 冲突风格 | 谁先破冰、修复成功率高不高、是否升级 |
| 他为什么忽冷忽热 | 依恋维度（焦虑/回避） | 不确定性 | 靠近—撤退的节律、触发点 |
| 我们还有救吗 | 修复尝试 + 投入模型 | 5:1 正负比 | 修复是否被接住、投入是否还在 |

## 三条使用规则

1. **框架只用来组织观察，不用来下诊断。**
   可以写「他的行为符合高回避维度的特征」，不能写「他是回避型依恋」。
   前者是描述，后者是需要临床评估的结论。

2. **每个判断至少挂一个构念 + 一条原文。**
   格式：`框架构念 → 对应的行为 → 原文证据`。
   只有原文没有构念，是观感；只有构念没有原文，是套模板。

3. **标注证据强度。**
   - 强：多次出现、有明确行为、有第三方信息
   - 中：出现 2–3 次、行为明确但样本少
   - 弱：单次事件、或依赖推断

## 这些理论的局限（必须写进报告）

- 绝大多数研究的样本是**西方、已婚、异性恋、中产**夫妻/情侣，跨文化适用性有限。
- Gottman 的离婚预测准确率有方法论争议（Heyman & Slep, 2001），
  这里只用他的**描述性发现**（四骑士、修复尝试），不用预测结论。
- 依恋类型的测量依赖量表，聊天文本只能给维度倾向，不能给类型。
- 相关不等于因果：聊得少可能是关系冷了，也可能是两个人本来就不爱发消息。
