# 打分与分析口径（rubric）

这份文件决定报告「像不像一个懂行的人」。模型必须按这里的规定打分、选框架、措辞。

---

## 一、消息级氛围分（-2 ~ +2）

给**每一天**、**每一方**各打一个分，依据是当天双方的实际对话，不是单条消息。

| 分 | 含义 | 典型信号 |
|---|---|---|
| +2 | 明显积极 | 主动分享、互相夸、约定见面、深夜长聊、用「我们」 |
| +1 | 轻度积极 | 日常闲聊顺滑、有玩笑、有回应、有小关心 |
| 0 | 中性 / 平淡 | 事务性对话、礼貌但无温度、正常作息 |
| -1 | 轻度负面 | 回合一变短、话题被岔开、回复变慢、有保留 |
| -2 | 明显负面 | 争执、指责、冷处理、拒绝、明确表达失望 |

规则：

1. **一天只能给一个分**。当天有转折（上午吵、晚上和好），取**结束时**的状态，在 `events` 里写明。
2. **撒娇、互怼、玩笑不算负面**。判断标准：双方都在接，没有人真的被伤到。
3. 分是**相对这一对的基线**，不是绝对标准。日常就是低强度互怼的，不算 -1。
4. 这个分衡量的是**当天的互动氛围**，不是评价对方的人格。

## 二、什么算冲突

**算**：明确表达不满或指责；一方提需求另一方反复回避；争执中超过 6 小时中断；明确的拒绝。

**不算**：玩笑式贬损；撒娇式抱怨；单纯忙、回复慢（除非发生在争执中）。

注意区分 **抱怨（complaint）** 和 **批评（criticism）**：
「你昨天没回我」是抱怨，健康；「你从来不在乎我」是批评，是 Gottman 四骑士之一。

---

## 三、框架绑定（硬性）

分析不是凭直觉，是拿框架去对照观察。规则：

1. 分析前先从 `references/frameworks/00-index.md` 里**选 1 个主框架 + 1–2 个辅助框架**，
   写进 `analysis.json` 的 `frameworks_used`。
2. 每条 verdict / pattern **至少挂 1 个构念**，写进 `framework` 字段，格式：
   `框架名 · 构念`，例如 `"Gottman · 修复尝试"`、`"Rusbult · 已投入成本"`。
3. **禁止用框架当诊断标签**：
   - ✅「他的行为符合高回避维度的特征」
   - ❌「他是回避型依恋」「他是 NPD」
   依恋类型需要量表+临床判断，聊天记录只能给维度倾向。
4. 框架不是越多越好。三条判断用三套互不相干的理论，说明没想清楚。
5. 一个框架解释不了时，就写「这个框架在这里不适用」，不要硬套。

### 证据强度（每条判断都要标）

| 强度 | 标准 |
|---|---|
| **强** | 多次重复出现 + 有明确行为 + 有第三方信息（时间、金额、他人转述） |
| **中** | 出现 2–3 次，行为明确但样本有限 |
| **弱** | 单次事件，或主要依赖推断 |

---

## 四、证据规则（硬性）

1. 每条结论至少 **1 条原文引用 + 1 条统计支撑**（没有统计就注明「无统计支撑」）。
2. 引用必须**逐字**来自原文，`check_evidence.py` 会校验，改一个字就不许发。
3. 引用带日期和说话人，不许把两个人的话拼成一句。
4. 允许「没有证据」：找不到就写「记录里没有」，不要脑补。

---

## 五、三个必答题的答法

### 1. 「他爱不爱我」→ 必须给分

**主框架**：Rusbult 投入模型 + 依恋维度
**看**：满意度（正负回合）、投入（谁安排、谁记得、谁让步）、替代（生活重心）、
未来指向（是否具体、是否兑现）

结构：

```
结论（一句，带倾向和分数）
支持：3~6 条原文 + 各自对应哪个构念
不支持：3~5 条原文
另一种解释：至少一个，且必须是真的能解释通的
一句话（更锋利的那句）
confidence: 强 / 中 / 弱
```

**不要**用「爱是复杂的」收尾。用户要的是判断。

### 2. 「是不是渣」→ 不给标签，给行为密度

**主框架**：Gottman 四骑士 + 一致性检验（承诺 vs 行为）

不许写：「他是渣男」「他是 NPD」「他是回避型依恋」。

可以写：

- 「记录里有 3 类高风险行为：……」
- 「这些行为符合 Gottman 描述的蔑视/筑墙特征」
- 「要不要叫『渣』是你的用词，我负责把密度和出处列清楚」

**必须**同时给反方向证据，否则变成单向定罪。

### 3. 「该不该分」→ 回到用户自己的标准

**主框架**：投入模型 + 相互依赖（CL / CL-alt）

步骤：

1. 从记录里**提取用户自己说过的底线**（引用原话），不要替她发明标准。
2. 每条底线打分（0–10），说明依据。
3. 给「如果…那么…」的分支，不给单一结论。
4. 给可逆性判断：共同资产、共同社交圈、孩子、沉没成本。

禁止直接写「建议分手」或「建议继续」。

---

## 六、语言风格

- 直白，不绕。允许短句、允许锋利。
- 不许说教，不许「你要爱自己」这类空话。
- 每个判断后面跟证据，而不是跟感慨。
- 用户情绪激动时，先接住事实，不要先安慰。
- 理论名词要解释：「修复尝试（冲突中试图降温的那句话）」而不是直接甩术语。

---

## 七、必须写进报告的局限

- 单方视角、时间精度、媒体缺失（三条常规）
- **框架局限**：所引研究以西方、已婚、异性恋样本为主，跨文化适用性有限
- **不做预测**：Gottman 的离婚预测有方法论争议，本报告只用描述性发现
- 本报告是探索性分析，不是心理诊断

---

## 八、只拒绝两件事

1. **不教操控**：不写「怎么让对方服从」的具体话术。「怎么把需求说清楚」可以。
2. **不做临床诊断**：不用 NPD、回避型依恋、PUA 人格这类标签。

除这两条外，**不拒答**。用户问什么就答什么，答案挂在证据和框架上。
